# PiCareer Support：项目计划与执行清单

当前阶段：后端骨架、模型及数据层选型已确认，其他技术规划待完善；开发尚未开始。下一步继续 P1 资料与场景基线整理，并补齐 P2 的待定方案与知识覆盖清单。

## 1. 项目目标

构建独立的前后端分离应用，以 **PiCareer 为被支持的软件产品**，提供有依据的问题解答、交互排障、工单创建与跟踪。

项目同时作为 AI Agent 应用开发的学习与实习展示作品。主要目标是实践《已学的全部知识点.md》中的全部知识点，分别通过业务功能、可运行的对照实验或选型说明体现。控制工程复杂度，不要求所有替代技术同时进入正式业务链路。

现有 PiCareer 是产品资料来源和测试对象；新项目独立开发。

## 2. 用户与业务闭环

**用户角色**

- 产品用户：咨询使用方法、报告故障、补充信息、确认操作、查看工单。
- 支持人员：维护产品知识、处理工单、记录解决方案。
- Agent：查询资料、澄清问题、辅助诊断、整理答复和工单。

**主流程**

提出问题 → 补充必要信息 → 检索资料与历史案例 → 按需查询诊断信息 → 提供带来源的方案 → 用户反馈是否解决 → 未解决则生成工单草稿 → 用户确认创建 → 支持人员处理 → 用户确认解决并关闭。

**具体业务**

| 业务 | 预期行为 |
|---|---|
| 使用咨询 | 回答安装、配置、功能使用和数据恢复等问题，注明适用版本与资料来源 |
| 交互排障 | 收集版本、运行环境、错误现象和已尝试操作；按步骤给建议，根据反馈继续判断 |
| 信息查询 | 查询产品版本、已知问题、历史工单及经用户提供的诊断信息 |
| 工单创建 | 汇总问题、环境、复现步骤、已尝试方案和证据；展示草稿，经确认后创建 |
| 工单跟踪 | 展示编号、处理状态、补充消息、处理记录和解决方案 |
| 知识准备与案例整理 | 首版手动导入资料并建立索引；经支持人员审核，将已解决工单整理为供后续手动导入的案例，暂不实现知识更新与索引同步 |
| 连续处理 | 保存会话和任务进度；关闭页面后可继续，明确展示失败、取消及待确认状态 |

首版工单状态：**待处理、处理中、待补充、已解决、已关闭**。支持人员更新处理状态，用户可补充信息并确认关闭。

## 3. 首版范围与业务约束

- 前端包含：支持对话、我的工单、支持管理三个主要入口。
- 首批覆盖 PiCareer 的支持问题：安装与配置、模型连接、通用聊天、简历材料处理、岗位检索、数据备份与恢复。这里的数据备份与恢复指 PiCareer 的使用咨询，支持系统自身暂不实现备份恢复功能。
- 知识材料以 PiCareer README、功能说明、版本记录、核实过的故障案例为基础，记录来源及适用版本。
- 当前资料基线为 PiCareer 0.1.15；保留资料版本作为引用信息，首版暂不实现检索版本过滤；资料冲突时核对后使用。
- 首版采用文本检索，保留图片引用、资料来源和 PDF 页码，不生成图片向量。现有知识 JSONL 作为首批导入源。
- 资料手动导入后建立检索索引；暂不实现知识更新与索引同步、版本过滤和支持系统自身的备份恢复。
- 资料不足时说明缺口并追问；不编造故障原因、引用、执行结果或工单状态。
- 诊断以只读信息查询和用户提供的材料为主；首版不远程执行用户电脑上的修复命令。
- 使用独立的演示工单服务。模拟故障、状态及案例必须标注，不冒充真实线上记录。
- 不导入真实密钥、个人简历、私人聊天、应用数据库或含个人信息的运行截图。
- 首版聚焦一个产品、一个演示工作空间；复杂企业组织、计费、跨企业隔离及外部客服平台对接留待扩展。
- 已确认的后端方案见第 4 节；MCP、多 Agent、Skills 的具体落地方式、评测及前端方案仍待讨论，接口细节在对应阶段确定。

## 4. 已确认技术选型

以下为已确认的规划，尚未实现或验证模型调用、存储、检索及部署。

| 部分 | 确定方案 |
|---|---|
| 后端基础 | Python、FastAPI、Pydantic、Uvicorn |
| 工程组织 | 模块化单体，按会话、知识、工单、Agent 等职责划分模块 |
| Agent 与编排 | LangGraph 管业务流程，LangChain 实现 Agent 节点 |
| LLM | API 调用 DeepSeek-V4.1-Flash |
| 嵌入模型 | API 调用阿里 qwen3-vl-embedding |
| 检索与精排 | Milvus 稠密向量与内置 BM25 混合召回，后端调用阿里 gte-rerank-v2 精排 |
| 数据持久化 | PostgreSQL 保存业务数据、知识正文和 Agent 状态；Milvus 保存可重建的索引及检索所需字段 |
| 数据访问与迁移 | SQLAlchemy 异步接口、Psycopg 3、Alembic；LangGraph 的 PostgreSQL 存储组件单独管理检查点和长期记忆 |
| 记忆 | PostgreSQL 检查点支持会话恢复；跨会话记忆经用户确认，支持查看与删除 |
| 文件与部署 | PDF、图片等文件存本地持久化目录，数据库记录文件信息；Windows 开发，Docker Compose 在 Linux 单机部署 |

**检索链路**：qwen3-vl-embedding 生成稠密向量，Milvus 内置 BM25 生成稀疏向量；两路召回融合后，由后端调用 gte-rerank-v2 对候选文本精排，再交给 Agent 生成带来源的回答。

**API 配置约定**：后续创建 `.env`，只定义字段，所有值留空，由用户自行填写；本次仅更新 README，不创建配置文件。

```dotenv
LLM_API_BASE=
LLM_API_KEY=
LLM_MODEL=
EMBEDDING_API_BASE=
EMBEDDING_API_KEY=
EMBEDDING_MODEL=
RERANK_API_BASE=
RERANK_API_KEY=
RERANK_MODEL=
```

上述模型分别按表中的已确认选型配置；实际 API 地址、协议及供应商接受的模型 ID 在接入时核对，不把未运行的连接测试记为通过。

## 6. 验收与 AI 执行规则

**核心验收场景**

- 已知问题：回答正确，引用能定位到适用版本的原文。
- 信息不足或资料冲突：先澄清或说明限制，不直接给出确定结论。
- 排障未解决：保留已尝试步骤，并准确带入工单草稿。
- 工单未经确认不创建；重复提交不会生成重复工单。
- 工具失败、任务取消或刷新页面：状态准确，历史可恢复，不重复执行已完成操作。
- 工单从创建到关闭有完整记录；只有审核后的解决案例可作为后续手动导入的知识材料，首版不要求工单自动同步到知识索引。
- 模拟数据有明确标识；知识覆盖清单中的每项均有可检查的证据。
